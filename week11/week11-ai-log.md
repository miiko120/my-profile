# Week11 AIと考えたログ

## Part 1：AIと考えた1セッション

### テーマ
Reactにおけるexportの役割と書き方についての質問

### 送った指示（良いプロンプトの型）

目的: Reactでのexportの仕組みと、どこに書くべきかを理解したい
前提: 自分のコード（App.jsx）でexportが必要な理由がよく分かっていない
見てほしい観点: exportの意味、種類、実際のコードでの適切な配置場所
制約: 初心者にも分かりやすく、具体例を交えて説明すること
出力形式: 解説とマークダウンのコード例

### 返ってきた出力（要約）

`export` はファイルを外に出す（他のファイルで `import` できるようにする）仕組み。代表的な `export default` と複数出力する普通の `export` があり、コンポーネント（App.jsxなど）では関数の外側または関数宣言の頭に記述する。

### "なぜ"を聞いた記録

- 聞いたこと: どこにexportって書けばいいの？
- 返ってきた説明（要約）: 関数の外側（ファイルの最下部など）か、`function App()` の直前に `export default` を付与することで、他のファイルからコンポーネントとして読み込めるようになる。
- 聞く前は分からなかったが、聞いて分かったこと: 関数の波かっこ `{}` の内側の中に書くのではなく、ファイル全体の末尾（外側）に独立して書く必要があること。

### 出力の4分類

| 分類 | 内容 | 判断理由 |
|---|---|---|
| 採用する | 一番下に `export default App;` を書くパターン | コードの構造がすっきりして初心者にも理解しやすいため |
| 保留する | 1行目に `export default function App()` と直接書くパターン | 動作は同じだが、まずは末尾に書く基本形に慣れたいため |
| 採用しない | Reactコンポーネントで `export default` なしの通常 `export` のみを使う案 | 単一コンポーネントファイルでは `default` を使うのが一般的で統一感が崩れるため |
| 要確認 | `App.jsx` 内のコンポーネントを分割した際の相対パス記述 | 別フォルダに移動した際の `import` パスの書き方は改めて確認が必要なため |

## Part 3：今後のAI利用方針

### Week11で気づいたこと

AIにコードの書き方を聞くだけでなく、「なぜその場所に書くのか」「なぜそのキーワード（export等）が必要なのか」という理由まで深掘りして質問することで、ただコピペするだけではなく自分の知識として定着することを実感した。

### 自分のAI利用ルール

1. 生成されたコードを貼り付ける前に、必ず各行の役割と意味を説明できるようにする。
2. 不明な記述やエラーが出た場合は、単に「直して」と聞くのではなく「なぜこのエラーが起きたのか」「この書き方の意味は何か」を最低1回は質問する。
3. コード全体を丸ごと出力させず、修正が必要なポイントと理由をピンポイントで解説させる。
